# 日常三件套：日结 / 日启 / 反思

一套经过长期实战打磨的个人工作流，由三个命令驱动：**日结**（归档）、**日启**（启动简报）、**反思**（系统改进）。核心设计：日志是记忆、行动板是任务源、反思是系统体检。

## 配置约定

所有路径基于当前工作区根目录，可在各命令文件的「配置」表中按环境修改：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `LOG_ROOT` | `0-工作日志` | 领域日志根目录 |
| `EXTRA_LOG_DIRS` | `运动日志` | 额外的扁平日志目录 |
| `BOARD_FILE` | `ACTIVE_BOARD.md` | 行动板：Now / Waiting / Next / Parked |
| `REPORT_DIR` | `${LOG_ROOT}/复盘` | 反思报告与每周学习归档目录 |
| `SECONDARY_WORKSPACE` | 空 | 可选：第二工作区（双区反思用） |

典型目录结构：

```
<workspace>/
├── 0-工作日志/<领域>/YYYY-MM-DD.md   ← 日结归档（领域自适应）
├── 运动日志/YYYY-MM-DD.md            ← 扁平日志（如运动）
├── ACTIVE_BOARD.md                   ← 行动板：Now / Waiting / Next / Parked
└── 0-工作日志/复盘/
    ├── 反思_*.md                     ← 反思报告
    └── 每周学习_*.md                 ← 每周外部学习
```

- 配置了 `SECONDARY_WORKSPACE` 时：属于该区的主题 → 引导去那个工作区归档，不在本区记。

## 日结（触发：「日结」「归档今天」「写日志」）

你是工作日志归档助手，基于当前对话内容归档：

1. **判断领域**：扫 `LOG_ROOT` + `EXTRA_LOG_DIRS` 已有领域，按对话主题关键词匹配（领域表见 `commands/daily-close.md` 配置）；**匹配不上→询问用户新领域名再建目录**，不强行塞"综合"。
2. **第二工作区任务**：属于 `SECONDARY_WORKSPACE` → 引导用户去那边归档，不在这记。
3. **新建或追加**：目标 `LOG_ROOT/<领域>/YYYY-MM-DD.md` 不存在→新建；已存在→读取→末尾追加 `## 🔄 会话 #N — HH:MM`→更新顶部 `## 📌 今日总览`（不重复已有决策/产出）。
4. **格式**（见 `templates/daily-log-template.md`）：今日总览 + 每会话 7 节：①本次状态（3 句）②已确认的决策表 ③关键产出表（✅/🔄/⏸）④待办（🔴高/🟡中/🟢低）⑤关键数字&参数 ⑥中断点 ⑦会话统计。
5. **行动板**：写完后更新 `BOARD_FILE`，给本次任务定状态：`Done`（完成）/ `Waiting`（等反馈，写清等什么）/ `Next`（还要继续）/ `Parked`（暂缓，不再日启提醒）。连续多次停在"等待确认"→ 改成三选一：通过 / 小修一次 / 暂挂。
6. **提取原则**：宁可多记不要漏；写清楚"为什么"；中断点要具体；路径用绝对路径；数字要精确；只记新内容。
7. **收尾汇报**："已归档到 [领域] → [路径]；行动板：Done/Waiting/Next/Parked"；追加模式报"今日该领域已归档 N 个会话"。

## 日启（触发：「日启」「开工」「今天做什么」）

30 秒启动简报，**只读不写文件**：

1. **行动板优先**：读 `BOARD_FILE`，建议来自 `Now`→`Waiting`→`Next` 优先级；有交接文件（如 `CODEX_HANDOFF.md`）就读其 `Latest`（只提相关 1-3 条）。Now 今天只推 1 个主任务；Waiting 超 2 天给三选一；Next 仅当 Now 无动作时才推。
2. **扫日志**：列出 `LOG_ROOT` + `EXTRA_LOG_DIRS` 各领域，取最近 3 天内日结，提取 `📌 今日总览`、`⑥ 中断点`、`🔴 高优先` 待办。
3. **级别**：所有领域更新 ≤7 天 → 精简简报；任何领域 >7 天或昨天无日结 → 完整简报（追加领域状态表 + 提醒补记/遗忘任务）。
4. **工具体检（可选，≤3 秒，只报异常）**：若配置了 `TOOL_CHECK_CMD` 则探活，失败才提示一行。
5. **输出格式**：
```
🎯 当前行动板
Now: ...  Waiting: ...
📍 上次进度
• [领域]: [中断点一句话]
💡 今日建议
[一句话]
🔴 待办提醒
- [ ] ...
```
6. **原则**：30 秒内完成、信息优先、跨领域汇总、不新建文件、不重新激活旧待办（行动板优先）。

## 反思（触发：「反思」「周反思」）

模式：`反思`（单区默认）｜`反思 双区`（+第二工作区）｜`反思 学习`（只跑外部学习）｜`反思 双区 学习`。

1. **扫 14 天日志**（默认单区：`LOG_ROOT` + `EXTRA_LOG_DIRS`；双区追加 `SECONDARY_WORKSPACE/日志/工作日志/*/`），跳过沉寂领域；读 `BOARD_FILE` 确认任务状态。
2. **分析维度**：🔄 重复模式（反复讨论未固化的决策、反复出现的问题）、⏰ 时间陷阱（启动慢、轮次多）、📋 待办积压（🔴 跨日志未完成、标了"下次做"从没做的）、🧩 指南健康度（过时路径/规则）、🔧 工具和工作流（可自动化的重复操作）。可访问的同期会话（含归档）也应核对；按消息日期判断期间，说明覆盖缺口，不能把缺日结推断为没工作。
3. **Token 消耗审计**：静态检查（推理强度、指南行数、Agent 文件数、MCP 数量、记忆文件数、`.claude/` 体积）；配置了 `SESSION_REPORT_DIR` 时补充量化数据；未配置则跳过量化部分，不硬凑。
4. **每周外部学习（每周最多一次，去重）**：先看本周是否已有 `每周学习_*.md`（有→只读引用+勾选上周"已落地/未落地"跟踪列；没有→执行扫描）。数据源：GitHub Trending（weekly）+ 网络搜索，按 **主线**（读 `LEARNING_STATE_FILE` 的 `current_phase` 定关键词）与 **工作线**（AI 工具链/MCP/自动化/写作）各搜 2-3 词，挑 **3-5 条**（新鲜≤7 天、相关、可落地、主线条目优先），每条带来源/通道/为什么值得学/下周怎么用/优先级（🔴🟡🟢），写入 `REPORT_DIR/每周学习_YYYY-MM-DD.md`，文件头记当前主线·周 N，末尾记计划检查点（是否反写学习计划进度）。
5. **输出反思报告**：活跃度总览表 + 重复模式 + 时间/Token 陷阱 + 积压待办表（要么做要么删）+ 指南健康检查 + Top 3 行动优先级 + Token 审计 + 每周外部学习段；写入 `REPORT_DIR/反思_YYYY-MM-DD.md`。完整列出有证据的不同问题，不以 Top 3 截断；逐项写来源、影响、可能原因、具体改法与责任，区分已完成、候选、未核实。先复核上次修正是否在真实工作中生效；简短状态更新不能代替完整反思。
6. **原则**：基于数据不是感觉（引用具体日志或会话）；建议可执行（"在 X 文件加 Z"）；区分轻重；不重复日启（日启=今天做什么，反思=系统怎么改进）；跨区只挂账不执行（双区发现最多在对方区行动板写一行指针）；向内也向外；学习要闭环（连续两周未落地且无原因的条目删掉）。真实使用暴露缺陷时修正现有技能/命令并验证；通用修正可同步源项目，私人路径与项目事实不入库。

## 关键提示

- 触发词就是三个词：「日结」「日启」「反思」——不要用长句指令替代。
- 文件是记忆、对话是草稿纸：落盘完成后对话可关。
- 详细逻辑以 `commands/daily-close.md`、`commands/daily-start.md`、`commands/daily-reflect.md` 为准（本文件是入口总览，命令文件是完整指令）。
