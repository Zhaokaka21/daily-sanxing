# 示例：反思报告

以下是一个真实的反思报告示例，展示 `daily-reflect`（反思）命令的输出结构。单区模式 + 每周外部学习。

## 输入场景

周日晚上跑 `/反思`。最近 14 天有 3 个活跃领域（读书、运动、写作），行动板有一个积压任务。本周还没有 `每周学习_*.md`。

## 输出（反思报告）

```markdown
# 🔍 工作流反思 — 2026年01月18日

> 扫描范围：最近 14 天（单区模式：当前区 3 个活跃领域；1 个沉寂领域略过）

## 📊 活跃度总览
| 工作区 | 领域 | 最近更新 | 14天会话数 | 状态 |
|--------|------|---------|-----------|------|
| 当前区 | 读书 | 昨天 | 6 | 🟢 |
| 当前区 | 运动 | 1月10日 | 3 | 🟡 |
| 当前区 | 写作 | 1月15日 | 2 | 🟡 |
| 当前区 | 摄影 | 12月20日 | 0 | 🔴 沉寂 |

## 🔄 发现的重复模式
1. **[「下次读」从未被读]** — 读书日志 3 次标了"下次读第 X 章"，但下一次会话都从别处开始。
   - 出现次数：3 次（1/12、1/14、1/16）
   - 建议：在行动板 Now 固化"下一章 = 待办"，日启时优先推。

## ⏰ 时间/Token 陷阱
1. 运动日志每次都要手动解释动作名称 — 建议把常用动作写进配置关键词表。

## 🧩 指南健康检查
- ✅ 领域路由表覆盖 3 个活跃领域
- ⚠️ 配置里的旧路径 `D:/old-notes` 已失效

## 🎯 本周优化建议（Top 3）
1. 行动板固化"下一章"待办 — 解决重复模式
2. 更新配置路径 — 消除无效引用
3. 摄影领域连续 4 周沉寂 — 移入 Parked 或删除

|--------|:--:|------|------|

| Agent 文件 | 🟢 | 2 个 | — |
| MCP 服务器 | 🟢 | 2 个 | — |

   - 可落地：下周用真实数据跑一次对比

> 计划检查点：主线工具落地后反写 `.skill-state.json` 进度（周学习 → 月计划闭环）
```

## 关键规则（命令内部逻辑）

1. **基于数据不是感觉**：每个发现引用具体日志；
2. **跨区只挂账**：双区模式跨区发现最多写一行指针，不越区改文件；
3. **学习要闭环**：每周条目带「已落地/未落地」跟踪列，连续两周未落地直接删；
4. **不重复日启**：日启=今天做什么，反思=系统怎么改进。
